# v0.2.41

## S6 内置 Console 更新

本版在 Console v0.2.39 的 Docker 构建成功并核验后发布。S6 基础镜像固定到该版本及已核验 digest，不再通过浮动 latest 决定内置 API 版本。

- 修复普通用户 CLI 指派越权、必须改密账户的 bearer 接口绕过，以及一次性部署 token 被并发超用的问题。
- 修复 OAuth 流程状态、错误身份资料和网页文案处理；旧地址簿标签同步只修改当前集合。
- 配置保存使用受限、独占创建的临时文件并验证 YAML；logout 和批量写入失败不再伪装成功。验证码缓存有界，非法 JWT duration 在启动时拒绝。
- 自有签名功能仍默认关闭，生成密钥后自动保存并提供一次性备份下载；现有 feature 文件无需重新生成。

部署 token 在设备副作用前领取额度，领取后即使部署/分配失败也消耗一次次数。批量地址簿操作仍不是全有或全无事务。

## 服务端与升级

hbbs/hbbr Rust 源码与 v0.2.40 相同；Classic 镜像不内置 Console，本次不增加新的路由协议能力。上游组件 Cargo 版本保持 1.1.17，发布标签继续使用本 fork 的版本序列。

S6 用户继续持久化 `/app/conf/features`，目录0700、feature 文件0600。已有启用用户重建前必须备份并迁移原 feature 文件，空 bind mount 不会迁移已有密钥；详见 `docs/client-capabilities.md`。独立部署 Console 的用户应单独更新到 v0.2.39。

## 验证与回归面

- Server 45 项库测试通过；本次仅修改 S6 Docker 基础镜像和发布说明，不修改客户端、shared 子模块、配置 schema 或 hbbs/hbbr 会话路径。
- Console 235 项 Rust 测试、7 项 Web 测试及构建通过；两个 musl 发布包均核对 SHA256，实际 x86 发布包通过健康检查、登录、密钥生成/脱敏、签名验签、无效 JWT 配置及 OAuth 模板烟测。
- 普通 Clippy/格式检查的已有警告与限制不在本次 Docker 更新中清理；不声称完整官方 Pro、WebRTC 协调、实时 ACL 或实际跨设备会话已经验收。
