# v0.2.40

## 客户端路由兼容性与登录门禁

- `MUST_LOGIN` 开启时，hbbs 的普通与 Switch Sides 打洞、中继协调入口统一要求有效账户 JWT 或目标绑定的切换授权。
- JWT 密钥为空时拒绝 token 路径，不再把任意非空 token 当作已登录；有效切换授权仍可独立使用。移除 token 生成时打印明文密钥的日志。
- `MUST_LOGIN` 关闭时保留原有免登录路由及打洞服务器公钥检查；不要求标准客户端未发送的 RequestRelay licence_key。
- 通过已有协议字段传递 IPv6 提示；客户端强制中继或服务端 `ALWAYS_USE_RELAY` 开启时跳过 LAN 直连分支。强制中继请求不广播 IPv6，服务端强制中继时也清除返回的 IPv6 提示。

这些改动不提供完整 WebRTC SDP/UDP 协调、实时账户撤销或目标连接 ACL，不中断已有会话，也不阻止绕过 hbbs 的客户端直连 IP。

## Console 与 S6 部署

本版在 Console v0.2.38 镜像构建成功并核验后发布，S6 使用该 Console 的内嵌双语自签网页文档、默认关闭的自签功能及一次性密钥备份。

Compose 新增 `/app/conf/features` 独立持久化挂载。启动前须创建主机目录并设置 `0700`；已有启用用户在重建容器前须安全迁移原 feature 文件。空目录挂载不会迁移旧密钥。详见 `docs/client-capabilities.md`。

配置签名密钥独立于 hbbs/hbbr 身份密钥与 JWT；生成后自动保存到 Console，并仅在生成时提供一次未加密 JSON 备份下载。自有配置需用户自行 fork 替换验签公钥并编译客户端，官方原版不信任该签名。

## 验证与回归面

- 45 项 Rust 库测试通过，all-targets/all-features 检查通过。
- 新增逻辑集中在 `routing_auth` 和 `transport_hints`；现有 rendezvous 路径仅接入必要鉴权和协议提示，hbbr 转发会话路径不变，不升级 shared 子模块。
- 普通 Clippy 仍被旧 `stream.write(...).await.ok()` 的 `unused_io_amount` 拒绝项阻断；仅在命令中放宽该已知旧项后检查通过，未为消警告改动旧 I/O 路径。
- 发布标签遵循本 fork 版本序列，上游组件 Cargo 版本保持 1.1.17。
